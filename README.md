# AI-Powered Credit Card Fraud Detection

An inference-only Streamlit app that detects potentially fraudulent credit-card
transactions using three deployed machine learning models: **XGBoost**,
**Random Forest** and a **Stacking Ensemble** (XGBoost + Random Forest +
Logistic Regression with a logistic meta-learner). The ensemble is the
recommended model for deployment.

## What it does

- **Predict** - pick a model, fill a transaction form (amount, history,
  velocity, merchant, country, device, flags) and get a fraud probability,
  risk level and model explanation signals.
- **Batch Detection** - upload a CSV of transactions, score all of them with the
  chosen model and download the scored results.
- **Data Analytics** - dataset KPIs, amount/hour/merchant/country patterns and
  full model performance: metrics table, ROC curves, confusion matrices and
  top-10 feature importance.
- **About** - pipeline and technical details.

## Models & imbalance handling

- `RandomForestClassifier` with `class_weight='balanced'`, tuned with a **recall-first**
  decision threshold (catches more frauds, accepts more false alerts)
- `XGBoostClassifier` with `scale_pos_weight` set from the training imbalance - the
  strongest standalone model (F1-optimal threshold)
- `StackingClassifier` over the above plus `LogisticRegression(class_weight='balanced')` -
  F1-optimal threshold, best overall balance
- Error metric for tuning: **F1-score** (3-fold CV, randomized hyperparameter search)
- Stratified train/test split (80/20); metrics reported on the hold-out test set

Hold-out results: XGBoost (AUC 0.974, F1 0.647), Random Forest (AUC 0.971,
recall-first recall 0.754), Stacking Ensemble (AUC 0.983, F1 0.644). The Stacking
Ensemble is recommended for deployment.

## Setup && run

```bash
pip install -r requirements.txt

python train_model.py        # optional: the app auto-trains on first launch
streamlit run app.py
```

or double-click `start_app.bat`.

## CSV format for batch detection

Required columns:

```
transaction_amount, avg_amount_30d, account_age_days, previous_chargebacks,
tx_last_1h, tx_last_24h, transaction_hour, merchant_category, country,
device_type, is_international, is_high_risk_merchant
```

`merchant_category` in `[grocery, restaurant, fuel, fashion, electronics, travel,
food_delivery, digital, financial, casino]`, `country` in `[US, IN, UK, DE, FR,
BR, AU, CA, SG, AE]`, `device_type` in `[mobile, desktop, tablet, pos]`.
Yes/No (or 1/0) accepted for `is_international` / `is_high_risk_merchant`.

## Technical details

- Preprocessing: `preprocessor.joblib` (StandardScaler + OneHotEncoder) is loaded
  and only `.transform()` is called - never `.fit()` on the app side.
- Inference only: no retraining, refitting or retuning occurs inside the app.
- Dataset is synthetic (simulated fraud patterns, ~1.6% fraud), generated by
  `data_gen.py` - suitable for demos and workshops.
